# 웹 푸시 알림 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** CRM 을 닫아 둔 PC 에도 채팅·DM·업무요청·팀업무 항목추가 알림이 도착하게 한다.

**Architecture:** 저장한 브라우저가 `/api/send-push` 에 **행 id 만** 보내고, 서버가 `service_role` 로 그 행을 다시 읽어 제목·본문·수신자를 정한 뒤 `web-push` 로 각 기기에 발송한다. 받는 쪽은 `public/sw.js` 서비스워커가 알림을 띄우고 클릭 시 해당 화면으로 보낸다. 중복 팝업은 억제가 아니라 **같은 `tag`** 로 합친다.

**Tech Stack:** React 19 (CRA 5) · Supabase (PostgREST + Realtime + RLS) · Vercel 서버리스 함수(ESM, 파일 하나로 완결) · `web-push` (VAPID)

**Spec:** `docs/superpowers/specs/2026-08-16-웹푸시알림-design.md`

## Global Constraints

- **테스트 방식**: 이 저장소에는 App.js 용 자동 테스트가 없다(단일 30k 줄 파일). 검증은 저장소의 기존 관행을 따른다 — `scripts/*.mjs` 실측 스크립트 + `node scripts/run-sql.js` 카탈로그 조회 + `CI=true npx react-scripts build` + CLAUDE.md 2절 회귀 체크리스트. **테스트 파일을 새로 만들지 않는다.**
- **서버리스 함수는 파일 하나로 완결**: `api/` 안의 `_` 시작 공유 모듈은 Vercel 이 번들에서 빼버려 함수가 아예 못 뜬다(과거 FUNCTION_INVOCATION_FAILED 500). `denyUnauthorized` 블록은 기존 5개 엔드포인트에서 **복사**한다.
- **환경변수 이름**: `VAPID_PRIVATE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. 둘 중 하나라도 없으면 **500 + 없는 이름을 응답에 적는다**(assign-db-sync 와 같은 방침).
- **VAPID 공개키는 코드에 커밋한다**(공개용 값). **비밀키는 저장소에 절대 넣지 않는다** — `배정DB_설정_로컬/`(gitignore 됨)과 `.env.local` 에만 둔다.
- **회귀 기준선**: 환경변수를 넣기 전까지 기존 알림 동작이 **100% 그대로**여야 한다. 푸시 실패(500·네트워크·구독 없음)는 전부 조용히 무시한다.
- **`tag` 규칙(앱·서비스워커 공통)**: 채팅 `chat-<channel>` / 업무요청 `crm-req-<id>` / 팀업무 `crm-team-<id>`. 기존 App.js 값과 **글자까지 같아야** 중복이 합쳐진다.
- **RLS**: 새 정책을 추가하지 말고 **옛 정책을 drop 하고** 만든다(PERMISSIVE 는 OR 로 합쳐져 오히려 풀린다).
- **`.limit(1000 초과)` 금지** — 전체 조회는 `fetchAllRows`(CLAUDE.md 2-5).

- [ ] **Step 1: 조치 SQL 작성**

```sql
-- 푸시구독_기기별_행_RLS.sql
-- 왜: ① 지금은 사람당 1행이라 사무실 PC 와 노트북 중 나중에 켠 쪽이 앞을 덮어쓴다.
--     ② 정책이 p_push_subscriptions_all 하나(is_approved())뿐이라 승인된 사람이면
--        남의 구독을 읽고 지울 수도 있다.
-- 현재 0행이라 옮길 데이터가 없다.

alter table public.push_subscriptions add column if not exists endpoint text;
alter table public.push_subscriptions add column if not exists device text;
alter table public.push_subscriptions add column if not exists last_ok_at timestamptz;
alter table public.push_subscriptions add column if not exists fail_count int not null default 0;

-- 사람당 1행 제약 제거 → 기기당 1행
do $$
declare c record;
begin
  for c in
    select conname from pg_constraint
     where conrelid = 'public.push_subscriptions'::regclass and contype = 'u'
  loop
    execute format('alter table public.push_subscriptions drop constraint %I', c.conname);
  end loop;
end $$;
drop index if exists public.push_subscriptions_user_name_key;
drop index if exists public.push_subscriptions_user_name_idx;
create unique index if not exists push_subscriptions_endpoint_uniq
  on public.push_subscriptions (endpoint);
create index if not exists push_subscriptions_user_name_idx
  on public.push_subscriptions (user_name);

-- 정책 교체 — 추가가 아니라 교체(PERMISSIVE 는 OR 로 합쳐진다)
drop policy if exists p_push_subscriptions_all on public.push_subscriptions;
drop policy if exists p_push_subs_select on public.push_subscriptions;
drop policy if exists p_push_subs_insert on public.push_subscriptions;
drop policy if exists p_push_subs_update on public.push_subscriptions;
drop policy if exists p_push_subs_delete on public.push_subscriptions;

create policy p_push_subs_select on public.push_subscriptions for select to authenticated
  using (public.is_approved() and user_name = (select p.name from public.profiles p where p.id = auth.uid()));
create policy p_push_subs_insert on public.push_subscriptions for insert to authenticated
  with check (public.is_approved() and user_name = (select p.name from public.profiles p where p.id = auth.uid()));
create policy p_push_subs_update on public.push_subscriptions for update to authenticated
  using (public.is_approved() and user_name = (select p.name from public.profiles p where p.id = auth.uid()))
  with check (public.is_approved() and user_name = (select p.name from public.profiles p where p.id = auth.uid()));
create policy p_push_subs_delete on public.push_subscriptions for delete to authenticated
  using (public.is_approved() and user_name = (select p.name from public.profiles p where p.id = auth.uid()));

alter table public.push_subscriptions enable row level security;
revoke all on public.push_subscriptions from anon;
revoke truncate, references, trigger on public.push_subscriptions from authenticated, anon;
```

### Task 3: 서비스워커 `public/sw.js`

**Files:**

**Interfaces:**
- Consumes: 서버가 보내는 payload `{ title, body, tag, url, kind, id }` (Task 4 가 만든다).
- Produces: 열려 있는 창에 `postMessage({ type: "push-shown", id, kind, url })` — Task 7 의 이중 방어가 받는다.

- [ ] **Step 1: 파일 작성**

```js
// CRM 웹 푸시 서비스워커 — 앱을 닫아도 알림이 오게 하는 유일한 경로.
//
// ⚠️ 이 파일은 **캐싱을 하지 않는다**(fetch 이벤트를 아예 다루지 않는다).
//    캐싱을 넣으면 배포해도 옛 화면이 남는 사고가 난다. 이 프로젝트는 이미
//    cache-buster.txt + BuildBadge 로 버전 갱신을 관리한다. 여기에 손대지 말 것.
//
// ⚠️ tag 는 App.js 의 알림 tag 와 **글자까지 같아야** 한다
//    (채팅 chat-<channel> / 업무요청 crm-req-<id> / 팀업무 crm-team-<id>).
//    같은 tag 여야 앱 팝업과 푸시 팝업이 하나로 합쳐진다. 다르면 같은 알림이 두 번 뜬다.

self.addEventListener("install", function (e) { self.skipWaiting(); });
self.addEventListener("activate", function (e) { e.waitUntil(self.clients.claim()); });

self.addEventListener("push", function (event) {
  var data = {};
  try { data = event.data ? event.data.json() : {}; } catch (e) { data = {}; }
  var title = data.title || "CRM 알림";
  var body = data.body || "새 알림이 있습니다.";
  var tag = data.tag || "crm-alert";
  var url = data.url || "/";

  event.waitUntil(
    self.registration.showNotification(title, {
      body: String(body).slice(0, 120),
      tag: tag,
      renotify: true,
      requireInteraction: true,   // 앱 팝업과 동일 — 사용자가 닫을 때까지 남는다
      icon: "/logo192.png",
      badge: "/logo192.png",
      data: { url: url, id: data.id || null, kind: data.kind || null },
    }).then(function () {
      // 열려 있는 창에 "내가 띄웠다"고 알린다 — 앱이 같은 id 로 팝업을 또 띄우지 않게 하는 이중 방어.
      // (기본 방어는 같은 tag 로 OS 가 합치는 것. 태그 대체가 안 먹는 브라우저 대비.)
      return self.clients.matchAll({ type: "window", includeUncontrolled: true }).then(function (cs) {
        cs.forEach(function (c) {
          try { c.postMessage({ type: "push-shown", id: data.id || null, kind: data.kind || null, url: url }); } catch (e) {}
        });
      });
    })
  );
});

self.addEventListener("notificationclick", function (event) {
  var url = (event.notification.data && event.notification.data.url) || "/";
  event.notification.close();
  event.waitUntil(
    self.clients.matchAll({ type: "window", includeUncontrolled: true }).then(function (cs) {
      for (var i = 0; i < cs.length; i++) {
        var c = cs[i];
        if (c.url && c.url.indexOf(self.location.origin) === 0) {
          // 이미 열려 있는 CRM 창을 앞으로 꺼내고, 어디로 갈지 알려준다(새로고침 없이 이동).
          try { c.postMessage({ type: "push-click", url: url }); } catch (e) {}
          return c.focus();
        }
      }
      return self.clients.openWindow(url);
    })
  );
});
```

### Task 4: 발송 엔드포인트 `api/send-push.js`

**Files:**
- Create: `api/send-push.js`

**Interfaces:**
- Consumes: `POST { kind: "chat"|"request"|"team"|"team_item", id: <행 id>, itemText?: string, targets?: string[] }` + `Authorization`/`x-supabase-anon` 헤더(App.js `callApi` 가 붙인다).
- Produces: `200 { ok, sent, removed, skipped }` / `500 { error }`(환경변수 누락) / `401`·`403`(인증).

- [ ] **Step 1: 인증 블록을 기존 엔드포인트에서 복사**

`api/ai-company.js:18-54` 의 `denyUnauthorized` 를 그대로 복사하되, **호출자 user id 가 필요**하므로
`{ denied: boolean, userId: string }` 을 돌려주는 형태로 바꾼다(사칭 검사에 쓴다).

- [ ] **Step 2: 본문 작성** — 클라이언트가 준 문구를 그대로 쓰지 않고 **DB 행에서 다시 만든다**

핵심 규칙 4가지를 코드 주석으로 남긴다:
1. 호출자가 그 행의 작성자(`sender`/`request_from`/`posted_by`)가 아니면 **403** — 남을 사칭한 푸시 차단.
2. 수신자 판정: `chat` → `rpc/chat_can_access`, `request` → `request_to`, `team*` → `targets` ∩ 승인된 사용자.
3. `itemText` 는 그 행의 `checklist` 에 실제로 존재할 때만 본문에 쓴다.
4. 발송 결과 `404`/`410` → 그 `endpoint` 행 삭제(만료 구독 청소), 그 외 실패는 `fail_count` 증가.

**Interfaces:**

- Produces: `notifyPush(kind, id, extra)` — 실패를 삼키는 fire-and-forget. **await 하지 않는다**(저장 흐름을 막으면 안 된다).

- [ ] **Step 1: 함수 추가**

```js
// 🔔 닫혀 있는 사람에게 보내는 진짜 푸시. 서버가 대상·문구를 DB에서 다시 정하므로
//    여기서는 "무엇을 알릴지"(종류 + 행 id)만 보낸다.
// ⚠️ 실패를 절대 위로 던지지 않는다 — 환경변수를 넣기 전에는 500 이 정상이고,
//    그 구간에도 기존 알림(열린 탭)은 그대로 동작해야 한다.
function notifyPush(kind, id, extra) {
  try {
    if (!kind || !id) return;
    callApi("/api/send-push", Object.assign({ kind: kind, id: id }, extra || {}))
      .catch(function () {});
  } catch (e) {}
}
```
