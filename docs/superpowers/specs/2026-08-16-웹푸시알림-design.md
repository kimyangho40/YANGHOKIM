# 웹 푸시 알림 (앱을 닫아도 오는 알림) — 설계

작성 2026-08-16 · 상태: 승인됨(구현 대기)

## 1. 왜 필요한가

지금 CRM 의 알림은 **탭이 열려 있고 Realtime 구독이 살아 있는 브라우저에서만** 동작한다.
`push_subscriptions` 테이블은 있지만 **0행**이고, 저장되는 값도 실제 푸시 endpoint 가 아니라
`{ endpoint: "browser-이름" }` 이라는 더미 문자열이다(App.js:6191·18749).
`sendPushToUser`(App.js:18622)는 이름과 달리 밖으로 아무것도 보내지 않고
**호출한 사람 본인 PC 에 `new Notification()` 을 띄울 뿐**이다(주석에도 "같은 PC에서만 작동").
서비스워커 파일도 등록 코드도 저장소 어디에도 없다.

→ 결과: **앱을 닫으면 어떤 알림도 오지 않는다.** 이 문서는 그걸 없애는 설계다.

## 2. 범위

**대상 기기: PC 브라우저(크롬·엣지)만.** 안드로이드·아이폰은 이번 범위가 아니다
(아이폰은 사파리에서 "홈 화면에 추가"를 각자 해야만 푸시가 오므로 별도 안내가 필요하다).

**푸시를 보내는 사건 4가지** (전부 본인이 만든 것은 제외):

| 사건 | 받는 사람 | 지금 상태 |
|---|---|---|
| 팀 채팅 새 메시지 | 그 채널을 볼 수 있는 사람 | 열린 탭에서만 알림 |
| DM 새 메시지 | 상대 1명 | 열린 탭에서만 알림 |
| 업무요청 도착 | `request_to` 1명 | 열린 탭에서만 알림 |
| 팀업무 카드에 **항목 추가** | 화면 알림과 같은 명단 | **알림 자체가 없음(신설)** |

**하지 않는 것**: 반복 알림("확인할 때까지 계속 울리기"), 모바일 푸시, 오프라인 캐싱.

## 3. 사용자가 겪는 동작

- 탭을 전부 닫아도 윈도우 오른쪽 아래에 알림창이 뜬다. 클릭하면 CRM 창이 이미 있으면 그 창이
  앞으로 나오고, 없으면 새로 열리며 **해당 화면(채팅 채널 / 요청현황 / 팀업무)까지 이동**한다.
- 1회 표시 + 윈도우 알림센터에 남는다. 같은 채널 메시지가 연속으로 오면 `tag` 로 최신 것으로 갱신된다.
- 소리·인앱 토스트·클릭 이동은 **지금 채팅과 완전히 같다**.

### 넘을 수 없는 제약 (사용자에게 미리 알린 것)
- **PC 를 끄거나 크롬을 완전히 종료하면 그때는 오지 않는다.** 브라우저의 "닫아도 백그라운드 실행"이
  켜져 있어야 탭을 다 닫아도 온다.
- **윈도우 알림이 꺼져 있으면(`ToastEnabled=0`) 여전히 아무것도 안 보인다.** 푸시로도 못 넘는다.
  (2026-08-16 노트북 사례 — 코드·권한 다 정상인데 OS 설정이 원인이었다.)

## 4. 구조

```
[보낸 사람 브라우저]  저장 후 → POST /api/send-push { kind, id }   ← 행 id 만 보낸다
        ↓
[api/send-push.js]   ① 로그인·승인 검사(denyUnauthorized)
                     ② service_role 로 그 행을 다시 읽어 제목·본문을 만든다
                     ③ 호출자가 그 행의 작성자인지 확인 (사칭 차단)
                     ④ 받을 사람을 판정 → push_subscriptions 조회
                     ⑤ web-push 로 각 기기에 발송, 410/404 는 행 삭제
        ↓
[받는 사람 브라우저의 sw.js]  push 이벤트 → showNotification → 클릭 시 창 포커스 + 화면 이동
```

**핵심 원칙: 클라이언트는 "무엇을 알릴지"만 말하고, "누구에게 무슨 문구로"는 서버가 정한다.**
그래서 임의 대상에게 임의 문구를 쏘는 사칭 푸시가 구조적으로 불가능하다.

### 4.1 받을 사람 판정 — 규칙의 복사본을 늘리지 않는다

채널 판정 규칙은 이미 **App.js `canAccessChannel`(3850) 과 SQL `chat_can_access` 가 한 쌍**이다
(CLAUDE.md 경고: 한쪽만 고치면 깨진다). 발송 서버에 **세 번째 복사본을 만들지 않는다.**

| kind | 받을 사람 판정 |
|---|---|
| `chat` | 구독이 있는 이름마다 DB 함수 `chat_can_access(channel, 이름)` 을 호출해 통과한 사람 |
| `request` | 그 행의 `request_to` 한 명 |
| `team` / `team_item` | 클라이언트가 넘긴 명단(`TEAM_MEMBERS` 기준)을 **승인된 사용자인지만** 서버가 확인 |

팀노트를 이렇게 두는 이유: 팀 구분은 접근 권한이 아니라 **분류**라서 누구나 모든 팀 노트를 본다
(CLAUDE.md). 명단은 "알림 대상"일 뿐이라 서버가 좁힐 근거가 없고, 원본을 App.js 한 곳에 남긴다.

### 4.2 중복 알림 방지 — 같은 `tag` 로 합친다 (억제하지 않는다)

지금은 앱이 열려 있을 때 앱이 직접 `new Notification()` 을 띄운다(6404 `showChatBrowserNotif` 등).
여기에 푸시가 더해지면 **같은 알림이 두 번** 뜰 수 있다(탭이 열려 있는 사람 한정).

**"푸시 구독이 있으면 앱은 팝업을 띄우지 않는다"로 만들면 안 된다.** 구독은 있는데 발송이 실패하는
구간(= 환경변수를 넣기 전, `/api/send-push` 가 500 인 지금)에는 **아무 팝업도 뜨지 않게 되어
멀쩡하던 알림이 통째로 사라진다.** 억제는 "푸시가 반드시 온다"를 전제하므로 쓰지 않는다.

→ 대신 **앱과 서비스워커가 같은 사건에 같은 `tag`** 를 쓴다(`crm-chat-<channel>`, `crm-req-<id>`,
`crm-team-<id>`). 같은 태그면 OS 가 쌓지 않고 **최신 것으로 대체**하므로 화면에는 항상 1개만 남는다.
푸시가 안 오면 앱 팝업이 그대로 뜨고, 푸시가 오면 같은 자리를 덮어쓴다. **어느 쪽이 실패해도
알림이 사라지지 않는다.**
보조로, 서비스워커가 열려 있는 창에 `postMessage({shown:id})` 를 보내 같은 id 에 대한 앱 팝업을
몇 초간 건너뛰게 한다(태그 대체가 안 먹는 브라우저 대비 이중 방어).

⚠️ **회귀 기준선: 환경변수를 넣기 전까지 기존 알림 동작은 100% 그대로여야 한다.**
푸시 실패(500·네트워크 오류·구독 없음)는 전부 조용히 무시하고 기존 경로에 아무 영향도 주지 않는다.

### 4.3 팀업무 "항목 추가"는 UPDATE 다 — 알림을 새로 만든다

사용자가 말한 "일자별 카드 안에 업무를 추가"는 실제로 **기존 행의 UPDATE** 다
(`saveEditNote` App.js:29316, 채팅→업무노트 병합 저장 4850). 그런데 실시간 핸들러는
**INSERT 일 때만** 알림을 만든다(6831, 주석: "UPDATE 는 확인·가져가기 같은 잡음").

→ **항목 수가 늘어난 UPDATE 만** 알림으로 친다. 확인(`read_by`)·가져가기·완료·내용수정은
항목 수가 변하지 않으므로 **자동으로 걸러진다**. 판정에 필요한 "이전 항목 수"는 App 레벨에
`teamItemCountRef`(노트 id → 항목 수) 캐시를 두고 구독 시작 시 채운다.
푸시는 저장한 브라우저가 `kind:'team_item'` 으로 알리고, 서버는 넘어온 항목 텍스트가
실제로 그 행의 checklist 에 있는지 확인한 뒤에만 본문에 쓴다.

화면 알림에도 **채팅과 같은 "그 화면을 보고 있으면 생략" 규칙**을 적용한다(사용자 요청).

## 5. 새로 만드는 것

### 5.1 `public/sw.js` — 서비스워커
- `push`: payload(JSON) → `showNotification(title, {body, icon, tag, data:{url}, renotify:true})`.
  payload 가 없는 깨우기에는 "새 알림이 있습니다" 폴백.
- `notificationclick`: 열려 있는 CRM 창이 있으면 `focus()` + `postMessage({url})`,
  없으면 `clients.openWindow(url)`.
- `install`/`activate`: `skipWaiting()` + `clients.claim()`.
- ⚠️ **`fetch` 이벤트를 다루지 않는다(캐싱 없음).** 캐싱을 넣으면 배포해도 옛 화면이 남는
  사고가 난다. 이 프로젝트는 이미 cache-buster 로 버전 갱신을 관리하고 있다.

### 5.2 `api/send-push.js` — 발송 엔드포인트
- 첫 줄에 **`denyUnauthorized(req,res)`**(CLAUDE.md 2-2). 다른 5개 엔드포인트와 같은 블록을 복사한다
  — `api/_auth.js` 같은 `_` 시작 공유 모듈은 **Vercel 이 번들에서 빼버려 함수가 아예 못 뜬다**.
- 입력 `{ kind, id, itemText?, targets? }`. 제목·본문은 서버가 DB 행에서 만든다.
- 발송은 `web-push` 패키지. `410 Gone`/`404` 응답이면 그 구독 행을 삭제한다(만료 청소).
- 환경변수 2개: `VAPID_PRIVATE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
  **둘 중 하나라도 없으면 500 + 어느 값이 없는지 알려준다**(assign-db-sync 와 같은 방침 —
  설치 중 원인을 못 찾는 게 더 위험하다).

### 5.3 VAPID 키
공개키는 **App.js 상수로 커밋한다**(공개되도록 설계된 값이라 안전하고, 환경변수를 하나 줄인다).
비밀키는 **Vercel 환경변수에만** 두고 저장소에는 절대 넣지 않는다.

### 5.4 SQL `푸시구독_기기별_행_RLS.sql` (+ `_rollback` / `_검증`)
- **사람당 1행 → 기기당 1행.** 지금 구조는 사무실 PC 와 노트북 중 나중에 켠 쪽이 앞을 덮어쓴다.
  `endpoint text` 추가 + `endpoint` 에 unique index, `user_name` 의 unique 제거.
  진단용 `device text`, `last_ok_at timestamptz`, `fail_count int` 추가.
- 정책 교체: 지금은 `p_push_subscriptions_all` 하나(`is_approved()`)뿐이라 **승인된 사람이면
  남의 구독을 읽고 지울 수도 있다.** → **본인 행만** 다루는 select/insert/update/delete 4개로 교체.
  본인 판정은 `user_name = (select name from public.profiles where id = auth.uid())`.
  ⚠️ 새 정책을 "추가"하면 PERMISSIVE 라 OR 로 합쳐져 오히려 풀린다 → **옛 정책을 drop 하고** 만든다.
- 발송 서버는 `service_role` 이라 RLS 를 우회하므로 영향 없다.
- anon 권한 0, `truncate/references/trigger` 회수 확인(CLAUDE.md 2-2 체크리스트).
- 현재 0행이라 옮길 데이터가 없다.

### 5.5 `scripts/send-test-push.mjs`
팀원을 안 울리고 **나에게만** 테스트 푸시를 보내는 스크립트(`node scripts/send-test-push.mjs 양호`).
`.env.local` 의 키를 읽어 로컬에서 직접 발송한다.

## 6. 바꾸는 기존 코드 (App.js)

| 위치 | 지금 | 바꿀 것 |
|---|---|---|
| 6191, 18749 | 더미 구독 upsert (`browser-이름`) | 실제 `pushManager.subscribe()` 결과 저장 |
| 18622 `sendPushToUser` | 본인 PC 에 로컬 알림 | 삭제 → `notifyPush(kind, id, extra)` |
| 4245 · 7830 · 8814 · 19379 | `sendPushToUser` 호출 | `notifyPush('request', id)` |
| 채팅 전송부 | 호출 없음 | `notifyPush('chat', id)` 추가 |
| 팀업무 INSERT 28972 | 호출 없음 | `notifyPush('team', id)` 추가 |
| 팀업무 UPDATE 29316 · 4850 | 호출 없음 | 항목이 늘었을 때만 `notifyPush('team_item', id, {itemText})` |
| 6404 `showChatBrowserNotif` 등 OS 팝업 3곳 | 제각각 `tag` | 서비스워커와 **같은 `tag` 규칙**으로 통일(4.2) |
| 6831 팀노트 실시간 | INSERT 만 알림 | UPDATE 중 **항목 증가**도 알림 |

공용 함수 `ensurePushSubscription(name)` 하나로 등록·구독·저장을 통합한다.

## 7. 검증

- `node scripts/send-test-push.mjs <내 이름>` 으로 **나만** 울리는지 실측.
- 탭 전부 닫고 → 다른 계정으로 메시지 전송 → 알림 도착 확인.
- 구독 만료(410) 시 행이 지워지는지 확인.
- `CI=true npx react-scripts build` 통과.
- CLAUDE.md 2절 회귀 목록 전부 — 특히 **채팅 알림 3종·팀업무 완료 자동 숨김·업무요청 3동작 독립·모바일 `/m`**.
  (모바일 `MobileApp` 은 `TeamNotesSection` 을 재사용하므로 팀업무 수정은 모바일에도 영향을 준다.)
- SQL `_검증` 스크립트로 정책 4개·anon 0건·unique index 확인. **조치 파일에 딸린 SELECT 를 믿지 말고
  실행 후 별도 조회로 다시 확인한다**(CLAUDE.md 2-2).

## 8. 배포 후 남는 클릭 (코드로 못 하는 일)

1. **Vercel 환경변수 2개 + Redeploy** — `VAPID_PRIVATE_KEY`, `SUPABASE_SERVICE_ROLE_KEY`.
   후자는 배정DB 동기화에 필요한 것과 **같은 변수**라 한 번에 처리된다.
   ⚠️ Vercel 은 환경변수를 추가해도 **기존 배포에 적용되지 않는다** — Redeploy 필수.
   ⚠️ 같은 레포에 Vercel 프로젝트가 3개 붙어 있다. **`crm`(= crm-beta-snowy)** 에 넣어야 한다.
2. 팀원 각자 CRM 접속 1회 (이미 알림을 허용한 사람은 자동으로 구독된다).

**환경변수를 넣기 전까지 `/api/send-push` 는 500 을 주고 실제 푸시는 나가지 않는다.**
그동안에도 기존 알림(열린 탭)은 그대로 동작한다 — 푸시 실패는 조용히 무시된다.
